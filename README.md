# SURAKSHA Grid (सुरक्षा ग्रिड)
### Intelligent Disaster Monitoring & Offline Emergency Response Platform

> **CRITICAL HONESTY NOTICE**: All satellite imagery feeds, satellite synchronization uplinks, and flood water level progressions in this demonstration are **SIMULATED**. Ordinary consumer smartphones do not connect directly to satellite broadband. Routes generated by the system are algorithmic recommendations based on known hazard inputs and are **never guaranteed safe**. In real operations, life-critical movements must follow on-ground authorities.

---

## 🌟 Executive Summary

**SURAKSHA Grid** is an offline-first disaster monitoring and emergency response web platform designed for severe monsoonal flooding, flash floods, landslides, and infrastructure collapse. Built for civilian survival and Emergency Operations Center (EOC) coordination, the platform combines:
- **Synthetic SAR-based flood extent visualization** with an interactive water-level surge slider.
- **Dynamic Dijkstra evacuation routing** that automatically identifies blocked roads and washed-out bridges, recalculating alternative high-ground paths in real time.
- **Offline-First IndexedDB SOS queueing** (via Dexie.js) allowing stranded citizens to capture and store distress packets with GPS telemetry even when cellular networks fail.
- **Simulated Satellite Burst Sync**, demonstrating how off-grid packets can be transmitted during satellite constellation passes.
- **Central EOC Command Dashboard** featuring priority-sorted triage (Critical > High > Moderate), shelter capacity monitoring bars, and specialized rescue team dispatching (NDRF, SDRF, Medevac).
- **Guided Presenter Tour**, allowing presenters and judges to walk through all 10 core disaster response steps in under 2 minutes.

## 🚀 Quick Start & Installation

### Prerequisites
- **Node.js**: v18.0.0 or later (tested on Node.js v24.15.0)
- **npm**: v9.0.0 or later (tested on npm 11.12.1)

### 1. Install Dependencies
```bash
npm install
```

### 2. Run Local Development Server
```bash
npm run dev
```
Open your browser at `http://localhost:5173/`.

### 3. Production Build & Preview
```bash
npm run build
npm run preview
```
Open your browser at `http://localhost:4173/`.

## ⚠️ Known Limitations & Real-World Production Roadmap

Deploying SURAKSHA Grid in actual disaster zones requires transitioning from simulated demonstration logic to hardened field infrastructure:

1. **Physical Satellite Hardware Bridging**:
   - *Limitation*: Consumer smartphones lack the physical phased-array antennas or RF power amplifiers to reach LEO/GEO satellites.
   - *Production Requirement*: Deployment of portable LoRa-to-Satellite gateways (e.g., Meshtastic nodes paired with Iridium 9603 SBD transceivers or RockBLOCK modules) or smartphones with 3GPP Rel-17 Non-Terrestrial Network (NTN) satellite messaging silicon.
2. **Live Satellite SAR Ingestion**:
   - *Limitation*: The demo uses mathematical flood polygon scaling based on water level.
   - *Production Requirement*: Automated API pipelines ingesting Sentinel-1 SAR GRD or NASA-ISRO SAR (NISAR) imagery via Copernicus Open Access Hub or ESA Earth Observation APIs, preprocessed through Cloud-Optimized GeoTIFF (COG) tiling servers.
3. **Real-World OpenStreetMap Road Topography**:
   - *Limitation*: The demo uses a curated, high-fidelity 12-node graph for deterministic presentation of primary vs alternative bypasses.
   - *Production Requirement*: Self-hosted OSRM (`osrm-backend`) or Valhalla routing instance loaded with full regional OpenStreetMap `.pbf` extracts, integrated with dynamic edge-exclusion APIs powered by emergency road closure databases.
4. **Regulatory, Spectrum & Telecom Approvals**:
   - *Limitation*: Wireless transmissions in emergency bands require legal compliance.
   - *Production Requirement*: National spectrum licensing for LoRa ISM bands (865–867 MHz in India, 915 MHz in US, 868 MHz in EU), satellite transponder regulatory clearance with local disaster management authorities (NDMA/State DMAs), and ISO 22320 emergency management compliance.
